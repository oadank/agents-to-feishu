# 团队任务账 taskboard

> 治什么：**同一件事被派两遍、两家改同一处互相覆盖、任务"完成"了又冒回待办、空口说做完**。
> 13 家 bot 只有一个裁判：配置中心的任务账。别在群里靠嘴对。

## 入口（都在配置中心同一个口，无新服务）

`http://127.0.0.1:13600`（Tailscale 也能开）。人看网页侧边栏「团队任务账」，机器走接口。

| 动作 | 怎么调 |
|---|---|
| 建账（派活先拿号） | `POST /api/tasks` body `{title,intent,shard,owner,dedupeKey}` |
| 领活 | `POST /api/tasks/T-0007/claim` body `{by:"你的名字",baseRev:6}` |
| 推进 / 交活 | `POST /api/tasks/T-0007/update` body `{by,baseRev,status,evidence,note}` |
| 查 | `GET /api/tasks?status=doing&shard=openmem` ｜ `GET /api/tasks/T-0007` |
| 体检 | `GET /api/tasks/board`（撞车/卡住/无证据/回炉全在这） |
| 闸门总账 | `GET /api/tasks/gate` ｜ 切档 `PUT /api/tasks/gate {mode}` |

## 六条硬规矩（都是服务端强制的，不是建议）

1. **`shard`（地盘）必填** —— 写清你要动哪块，例 `config-center` / `openmem` / `repo:agents-to-feishu` / `doc:团队铁律`。
   不知道动哪块 = 判不了撞车 = 不让建账。
2. **`dedupeKey`（幂等号）尽量填** —— 同一件事的号取同一个键（例 `fix-wb-storm-0920`）。
   重复派活命中它 ⇒ **不新建**，直接把旧那条还你并标 `duplicated:true`。
3. **同地盘只许一家在做** —— 第二家领活被拦，回体会告诉你是谁、哪一条。
   要么并成一件事，要么确认对方交棒后带 `takeOver:true` 重提（旧条自动转 blocked 并记原因）。
4. **写操作带 `baseRev`**（你读到的那一版）。对不上 ⇒ **本次不落账**、回显现状。
   🔴 **绝对不许硬盖别人的改动**：先看回显，能换算就换算后重提，不能就让路。
5. **状态只能朝前**：`todo → doing → review → done`（`blocked` 是 doing 的侧枝，待办→卡住算前进）。
   要倒退（例 `done → doing`）**必须带 `why`**，否则直接拒；写成功会进 `reopens[]` 留痕。
6. **标 `done` 必须带 `evidence`**（文件路径 / commit 哈希 / 链接 / 验收口径）。空口说完成不算完。

## 派活闸门会拦你（重要）

`lark_send_as_user` 给别的 bot 发消息时，若正文**像派活**（够长 + 带"帮我/你去/修复/实现/排查/验证/生成/整理…"这类词）
却**没带任务号**，会被服务端直接拒发。三种过法：

- ① **正规**：先建账拿号 `T-000X`，把号写进消息再发（推荐，别人接得上）。
- ② 这事已有账：把已有号写进消息（或用同一个 `dedupeKey`，不会新建）。
- ③ 真不是派活（纯传话/闲聊/回执）：正文加 `notask` 重发 —— 放行，但豁免计数上涨，老大看得见。

档位三档（`PUT /api/tasks/gate`）：`enforce`（默认，真拦）/ `observe`（只记账）/ `off`（全放）。
**别自己切档**，那是老大的权限。

## 汇报姿势

- 群里/私聊汇报**带任务号**（例：`T-0007 已交，证据 …`），别写"那个事做完了"。
- 交完活记得 `update` 回填 `evidence`，**别只发消息不落账** —— 落账的才算交付。

## 边界（别扩）

- 账本存 `~/.agents-to-feishu/runtime/taskboard/`，与 `config-store.json` **完全隔离**。
  不要因为"顺手"把任务写进配置文件 —— 那会把出厂设定搞脏（09-18 同类事故：闸门状态存 JSON 被两家同时写冲掉）。
- 账本读坏 ⇒ 报错停手，**绝不静默清空重建**（清一次等于抹掉全团队的活）。
- 只拦 bot→bot 派活。**人类消息永远不拦**，别把闸门往老大聊天上引。
